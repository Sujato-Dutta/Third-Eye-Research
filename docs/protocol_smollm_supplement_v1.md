# S1: four-state external SmolLM3 confirmation

Authorized October8,2026. This is a separately declared external confirmation
supplement, not an alteration or replacement of E2's balanced cohort or primary
comparison. Model identity is fixed to HuggingFaceTB/SmolLM3-3B. Resolve one
official public repository revision on a scheduled CPU node before outcomes;
pin it in all configurations and record/verify downloaded file checksums against
available official LFS hashes. No selection among model revisions by performance.

The fixed grid is code6142, code6143, math6142, math6143. Each invocation requests
one generation from the unchanged A2 protocol, potentially four early states
and twelve complete K=3 candidate labels. Retain parent, all M1/M2, accepted
weights and all failed/incomplete evidence. Seeds are not replaced, and single
states must not be described as a completed T5 third-backbone study.

Copy the existing Qwen task configuration and its immutable dataset manifest;
change only the backbone/revision, model-specific nonthinking chat configuration
and predeclared seed. LoRA rank16/alpha32/dropout0, LR1e-4,50 optimizer steps,
microbatch1, accumulation8, maximum sequence length1024, probe10, K=3, size2,
generation budgets, eight correction attempts, stride16, unique-within-batch
sampling and terminal M2=M1 remain unchanged. Training portions are1024 GSM8K
and306 MBPP prompts, with64/64/256 target/OOD/retention development examples.
Use only verifier-passing self-corrections in scientific labels.

Compatibility validation is mandatory before collection. CPU checks cover
native contracts, configuration preservation, official snapshot identity,
tokenizer assistant masking, the fixed grid and reserved scheduler capacity.
CUDA validation covers both task families, real50-step training, ten-step probe
rollback, checkpoint roundtrip, generation/conditional-likelihood evaluation,
unchanged parent preservation and the frozen forecaster input schema. Gold
training references may be used solely as compatibility fixtures; their adapters
are discarded and excluded from scientific states. Preflight pass/fail depends
on implementation compatibility, not accuracy thresholds. No harvesting-budget
or scientific optimization changes in response to validation.

The scheduled CPU setup can download models while core jobs wait. A lightweight
login dispatcher imports only the standard library and runs scheduler/metadata
operations. It requires successful setup, original core validation and the
validated core launcher-path repair before new GPU work. It reserves one slot
for every eligible core parent whose reliability job has not yet been submitted,
in addition to counting all currently queued/running GPU nodes. New work requires
occupied nodes + reserved core controls + one new node <=20. Additional jobs
therefore cannot occupy capacity required by future core callbacks.

Use a short gh-dev compatibility allocation, then at most four12-hour gh
single-state jobs as reserved capacity becomes available. Scientific jobs use
compute nodes only, with explicit successful-validation dependencies and runtime
passed-receipt checks. Stop new GPU submissions fourteen hours before the
October11 23:59:59 IST cutoff; enforce the cutoff inside each GPU process.
Submission receipts are saved after each job. Never blindly retry uncertain
submissions, swap failed states or keep GPUs allocated to poll for capacity.

After all four jobs end, a scheduled CPU review audits native A2 labels and
reports balanced coverage. Incomplete coverage stops the full comparison and
preserves all failures. Complete coverage yields observed immediate/random/
future-oracle selection values and regret, plus zero-shot predictions from the
already frozen original Direct-H2seed42 and matched-H1seed42 models. No new fit,
normalization, architecture selection or Gate2 replacement is permitted. The
new model is excluded from the original E2 primary population. Interpret its
four trajectories and two seeds per task cautiously; shared evaluation items
and small N limit inference.

No matched-noise supplement is added to this model in S1. Do not transfer the
two-backbone noise-floor conclusions to SmolLM3 without measurements. This
supplement supports limited two-step cross-backbone evidence. Save source,
model/config/data identities, coverage, results and checkpoints in a durable
work archive. Stop at scientific review, with no scaling or online rollout.
